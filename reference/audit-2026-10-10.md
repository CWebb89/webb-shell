# webb-shell — Audit 2026-10-10

Scope: whole tree excluding `reference/`. Baseline at audit time:
`qmllint --silent` exit 0, `bash -n` all of `bin/` + `install.sh` +
`portabilize.sh` OK, all seven node tests OK.

Mode: single-agent deep read of every project file, plus targeted runtime probes
for the shell-script findings. Findings are ordered by severity; each carries
`file:line` evidence and an honest confidence note.

This audit was run in preparation for publishing the repository, so documentation
accuracy is graded as a defect class rather than a footnote.

---

## F1 [High] `bin/clipboard.sh` copied nothing once history exceeded 200 entries

**Evidence**
- `bin/clipboard.sh:4` — `set -euo pipefail`
- `bin/clipboard.sh:6` — `choice=$(cliphist list | head -200 | .../menu-select.sh "Clipboard")`

`head` exits after 200 lines; `cliphist` is a Go binary writing to fd 1, so it
dies of SIGPIPE; `pipefail` propagates 141; the assignment fails; `set -e` aborts
before `wl-copy` on line 8. The picker opens, an entry is chosen, nothing is
copied. Data-dependent, so it works on a fresh machine and breaks as history
grows — this box had 750 entries.

**Probes**
- `cliphist list | head -200 >/dev/null` → `PIPESTATUS[0]=141`
- `bash -c 'set -euo pipefail; c=$(cliphist list|head -200|cat); echo REACHED'` → exit 141, no output
- the real script against a stub picker → `STUB-RAN`, exit 141, `wl-copy` never runs
- the same script with `pipefail` removed → exit 0, choice delivered, proving the pipe status is the cause and not the picker

**Fix** — bound upstream, not downstream: `mapfile -t` the whole list, slice to
200, feed the picker. Regression test `test/clipboard-script.js`.

## F2 [Medium] README documented the `dmenu` IPC contract wrong

`README.md` said `select <options> <prompt> <result-file>`. The handler is
`select(options, selectionFile, doneFile, prompt)` (`shell.qml`), and
`bin/menu-select.sh` passes four arguments in that order. Anyone writing a picker
from the README would have sent the prompt as the selection file and the result
path as the completion file. The table also omitted `bar settings`, `bar config`
and `notify center`/`centerHide`.

**Fix** — signature corrected, missing functions added, and the picker handshake
documented.

## F3 [Medium] CHANGELOG claimed notification action buttons that do not exist

`grep -r 'actions\|invokeAction' src/` returns nothing; the only matches in the
tree are in `reference/scotia/`. The toast delegate's sole interaction is
`MouseArea { onClicked: card.close() }`.

**Fix** — claim replaced with the actual behaviour.

## F4 [Medium] Test inventory drifted from the suite in both documents

Seven tests exist; `README.md` and `AGENTS.md` each listed four, omitting
`bar-config`, `bar-layout` and `popup-anchor`. **Fix** — both now glob `test/*.js`
instead of listing files, so the list cannot drift again.

## F5 [Medium] Toast dismissal addressed rows by index across a 200 ms window

`NotificationToasts.qml` — `card.close()` sets `closing`, starts a 200 ms timer,
then calls `dismissToast(card.index)`. `popupModel.insert(0, snap)` shifts every
surviving row's index, so a notification arriving inside that window made the
index point at the *new* toast: the wrong row was removed and the clicked card
stayed in the model at `opacity: 0`, still holding column height. The 5000 ms
expiry timer had the same race with a much wider window.

**Confidence** — mechanism read from source and checked against the
`Repeater`/`ListModel` contract; **not** reproduced at runtime, because this
machine has no key/click injection tool.

**Fix** — both timers resolve the row by `stem`, which is stable and unique.

## F6 [Low-Med] Two `bash -c` hand-offs interpolated values into shell source

- `MenuPopup.qml bumpUsage` built `... printf '%s\n' "<app id>" >> ...` by string concatenation. An id containing `"`, `` ` `` or `$(` would break quoting or execute.
- `MenuPopup.qml writeResult` interpolated the caller-supplied `selectionFile` / `doneFile` paths into the same string, from the `dmenu` IPC target.

The selection itself was already correctly base64-wrapped; only the paths were raw.
A scan of every installed `.desktop` on this box found no metacharacters, so the
`bumpUsage` case was latent rather than live. The same file already used the
correct argv-after-`--` pattern in `NotificationToasts.qml`.

**Fix** — both pass values as positional arguments. `writeResult` also now
returns early when there is no dmenu session instead of running `touch ""`.

## F7 [Low-Med] Wi-Fi PSK on the process command line

`NmcliService.connectTo` passes the passphrase as an nmcli argument, so it is
world-readable in `/proc/<pid>/cmdline` for the life of the run. The same
repository deliberately keeps its OpenRouter key out of argv
(`bin/openrouter-usage.sh` uses `curl -K <(...)`), so the two standards
disagreed. nmcli's `--passwd-file` / `--ask` options are documented for
connection profiles, not `device wifi connect`, and `man` is not installed on
this machine — the alternative is **unverified**, so it was not implemented.

**Fix** — documented as an accepted, deliberate exposure in
`AGENTS-REFERENCE.md`, with a warning not to "fix" it without checking the
installed nmcli's own `--help`.

## F8 [Low] `BtService` matched the bare substring `"ear"`

`isHeadphoneName` and `deviceIcon` treated any device containing `ear` as
headphones — Samsung `Gear`, `Clear`, `Wearable`, `Linear`, `Radar` — and showed
the headphone glyph in the bar. **Fix** — matched on `headphone`, `headset`,
`earbud`, `earphone`, `airpods`, `buds`; `deviceIcon` now calls the shared
predicate instead of repeating the list.

## F9 [Low] A second action while one was in flight was silently dropped

`NmcliService` (`connectTo`, `disconnect`, `refreshDetails`, `toggleWifi`),
`PulseService` (five setters), `SchemeSwitcher.applyCurrent` and
`MenuPopup.bumpUsage` set `running = true` without the `running = false` first
that the repository uses everywhere else (`SysStats.refresh`, `BtService`,
`PulseService.refresh`, `NmcliService.rescan`, `AgentUsage`).

**Fix** — reset added at each site, so the newer request wins instead of being discarded.

## F10 [Low] `bar-config.sh` persisted unvalidated anchor positions

`set-anchor` accepted any non-empty string, while its own usage header documents
nine positions and `src/components/PopupAnchor.js` already exports `isValid()`.
An invalid value was written to `config.json` and then silently rendered as
centered.

**Fix** — an `is_position` guard mirroring the file's existing `is_section`,
which rejects the value before `mutate` runs. All nine valid positions verified
accepted; `middle` and `""` rejected with the config left untouched.

## F11 [Low] Failed bar-config writes reverted the UI in silence

`BarSettingsPopup`'s `Process.onExited` popped its queue regardless of exit code
and never read stderr, so a rejected edit just snapped the board back.
**Fix** — stderr is collected and a non-zero exit raises a critical
`notify-send`, the same pattern `Reminders`/`UsbStorage`/`BatteryService` use.

## F12 [Low] `Colors.applyColors` accepted any key the JSON contained

`hasOwnProperty(key)` is true for read-only properties too, so a hand-edited
template carrying a derived token logged a read-only assignment, and one
carrying `colorsFile` could unmount the colour watch. The shipped template is
exactly correct (36 roles, derived tokens absent, verified key-for-key), so this
was a robustness gap rather than a live bug.

**Fix** — `derivedTokens` deny-list. A deny-list rather than an allow-list of the
writable roles because the failure modes differ: a new writable role missing from
an allow-list silently stops theming, while a new derived token missing from the
deny-list only logs.

## F13 [Low] Every `config.json` writer used a fixed temp filename

`bin/bar-config.sh` (`$CFG.new`), `ShellConfig.seedBar`/`persistMatugen`
(`$CFG.new`), `install.sh` and `bin/agent-default.sh` (`config.json.new`).
Concurrent writers clobber each other's temp file and the atomic `mv` then
publishes a half-merged document; a crash leaves the file behind.

**Fix** — `mktemp` beside the target (same directory, so `mv` stays atomic) with
the existing file's mode restored via `chmod --reference`, or `0644` on a fresh
install, matching what `cat > config.json` produced before. Verified: mode 640
preserved across writes, no temp files left after normal use, after rejections,
or after 20 concurrent writers.

## F14 [Low] `MenuModel.stripJsonc` was regex-based and lossy

`stripJsonc` used `,(\s*[}\]])` on the raw text — including inside string
literals — and stripped comments only when they began a line.

**Evidence**
- `{"a":{"label":"wat, } dah"}}` → `{"a":{"label":"wat } dah"}}` (silent corruption)
- `{"a": {"label": "A"} // trailing\n, ...}` → `JSON.parse` error
- one inline comment inserted into the real `menu.jsonc` → the entire document
  failed to parse, which degrades the menu to root-only

**Fix** — a string-aware two-pass scanner (comments, then trailing commas;
comments first so a comma before a comment is not left behind). 14 cases added to
`test/menu-model.js`, including escaped quotes and backslashes and a label
containing `//`.

## F15 [Low] Documentation and packaging staleness for publication

`CHANGELOG.md` opened with "This project is not under version control";
`README.md` credited `fzf` for the clipboard picker, which uses
`bin/menu-select.sh`; the notification daemon's action-button claim (F3) and the
test list (F4) are covered above. Packaging: `reference/scotia/` (2.1 M of a
different project) and the 17 `.pi/plans/` artifacts were in scope to publish.

**Fix** — CHANGELOG header, README requirement line, `.gitignore` for
`.pi/` and `reference/scotia/`, and a note in `reference/README.md` explaining
that `scotia/` is deliberately not published.

## Deliberately not changed

- **`Popups.exclusiveKeys` excludes `menuOpen`/`batteryOpen`/`printAnimRunning`.**
  Documented as intentional, and forcibly closing a dmenu-backed menu would skip
  `writeResult()` and hang its caller.
- **`install.sh` / `ShellConfig` interpolate a JSON blob into a `jq` expression.**
  The value is `JSON.stringify(defaultBar())`, locally generated and structurally
  valid, so there is no untrusted input in that path.
- **`MenuPopup.select(delta)` skips rather than visiting every index when
  `gcd(count, delta) != 1`.** Reachable only when every row in the stride is
  disabled; `delta` is 1 or 6 in practice.
- **`SystemMonitorPopup`'s 50 ms glow timer.** Already gated on
  `Popups.systemMonitorOpen`, so it does not run while the panel is closed.
- **`Delay.run`** was rewritten to instantiate from a `Component` instead of
  recompiling an inline QML string per call, but is otherwise unchanged.

## Verified clean

- `qmllint --silent shell.qml Bar.qml src/**/*.qml` exit 0; `bash -n` silent on
  all 31 scripts; all eight node tests pass.
- `menu.jsonc`: 419 items, no dangling parents, no empty submenus, every `open`/
  `toggle` hand-off resolves (only the two documented specials `reminder`/`bar`
  bypass the catalogue).
- matugen template ↔ `Colors` writable keys: 36/36 exact, derived tokens absent.
- Hardcoded hex values appear only in `Colors.qml`; no secret-shaped strings, no
  `/home/cwebb` paths in shipped project code; every `execDetached` and `Process`
  in the tree uses argv arrays.
- All 16 animated popups carry the `opacity: Popups.X ? 1 : 0` state binding.

## Not exercised

- **The toast index race (F5)** — no key/click injection available on this
  machine, so the fix is mechanism-verified only. The `stem` lookup is covered by
  construction, not by a test.
- **`quickshell -p .`** — a nonterminating visual smoke run that would create a
  second shell with duplicate layer surfaces over the live one. Not run.
- **Anything requiring a real wallpaper switch, Wi-Fi connect, or Bluetooth
  pair** — including F7's PSK exposure and F11's notification path.
